Clase 5 · 16 min

Estado fuera del modelo: archivos y git como memoria

En un loop largo, el contexto del modelo va a ser compactado, reseteado o cambiado por una sesión nueva. Lo que solo existía en la conversación desaparece o vuelve como resumen, mezclando hecho y suposición. La salida: sesión descartable, estado en archivos y en git, y todo ciclo empieza releyendo. Tú armas un ciclo así y lo interrumpes a propósito.

Empezar la lección

En esta lección vas a

  1. 1Por qué la memoria del modelo no aguanta un loop largo
  2. 2La lista de ítems con passes, el archivo de progreso y el git log
  3. 3Interrumpir y retomar sin rehacer ni saltar
  4. 4Git como deshacer y como historial del loop

Objetivo: armar un ciclo descartable que relee el estado en archivo, hace un ítem, verifica y hace commit, y retomar después de interrumpir sin rehacer nada.

La sesión termina o se cae; la siguiente empieza releyendo los archivos y sigue desde el primer pendiente.
1/6

Sesión nueva

Puede ser un /clear, una compactación, un codex exec nuevo, el Ralph llamando de nuevo u otra persona tomando el relevo. El diseño parte del peor caso: la sesión no recuerda nada y puede interrumpirse a la mitad.

Desplázate por la página: cada etapa de abajo ilumina su parte del diagrama.

  1. 1/6

    Sesión nueva

    Puede ser un /clear, una compactación, un codex exec nuevo, el Ralph llamando de nuevo u otra persona tomando el relevo. El diseño parte del peor caso: la sesión no recuerda nada y puede interrumpirse a la mitad.

  2. 2/6

    Relee el estado

    En el harness de larga duración de Anthropic (26/11/2025), toda sesión empieza así: dónde estoy (pwd), qué se hizo (git log y el archivo de progreso), cuál es el próximo ítem, y una prueba básica antes de programar. La lista de ítems es JSON con el campo passes; el post dice que el modelo sobrescribe menos el JSON que el Markdown.

  3. 3/6

    Hace un ítem

    Elige el primer ítem pendiente y hace solo ese. En el post de Anthropic, las sesiones siguientes solo pueden cambiar el campo passes; no reescriben ni borran ítems de la lista.

  4. 4/6

    Verifica y marca

    El ítem solo pasa a passes: true si la verificación de ese ítem pasó. La línea en el progreso dice cuándo y el resultado. Si falló, el ítem sigue pendiente y el motivo queda registrado.

  5. 5/6

    Commit

    El commit es el checkpoint: si la próxima sesión se cae, nada de lo que se verificó se pierde; si un ítem salió mal, git revert lo deshace. LOOP-R usa el mismo principio para las versiones del proceso ("git es el mecanismo de promoción y rollback"; detalle en el curso 5).

  6. 6/6

    Relee la carpeta, no la conversación

    La sesión es descartable; el estado no. Lo que necesita sobrevivir a una compactación, a un reset o a un cambio de modelo va a un archivo y a un commit antes del fin del ciclo.

El kit execucao-longa lleva la idea a siete archivos (goal, plan, state, progress, failures, decisions, canal): es la clase 1 del curso 2.

02 · Un ciclo descartable en Python

Cada ejecución es una "sesión" que no recuerda nada: relee, hace un ítem, verifica, graba y hace commit. Sin modelo: la acción es escribir un archivo.

Terminal · preparar la carpeta
mkdir -p ~/ensaio-loop/estado && cd ~/ensaio-loop/estado && git init -q
cat > features.json <<'EOF'
[
 {"id":"f1","descricao":"ler o CSV","passes":false},
 {"id":"f2","descricao":"contar linhas","passes":false},
 {"id":"f3","descricao":"gravar o resumo","passes":false}
]
EOF
git add -A && git commit -qm inicio
ciclo.py
#!/usr/bin/env python3
"""Un ciclo que empieza de cero cada vez: relee el estado en los archivos, hace UN ítem, graba y hace commit."""
import json, subprocess, sys, datetime, pathlib

estado = pathlib.Path("features.json")
itens = json.loads(estado.read_text())
pendentes = [i for i in itens if not i["passes"]]
if not pendentes:
    print("nada pendente: objetivo cumprido")
    sys.exit(0)
item = pendentes[0]
print(f"releu features.json: {len(itens) - len(pendentes)} feitos, {len(pendentes)} pendentes")
print(f"faz: {item['id']} ({item['descricao']})")
pathlib.Path(f"{item['id']}.txt").write_text(item["descricao"] + "\n")   # la "acción"
item["passes"] = pathlib.Path(f"{item['id']}.txt").exists()                # la "verificación"
estado.write_text(json.dumps(itens, ensure_ascii=False, indent=2) + "\n")
agora = datetime.datetime.now().strftime("%Y-%m-%d %H:%M")
with open("progress.md", "a") as f:
    f.write(f"| {agora} | {item['id']} | passes={item['passes']} |\n")
subprocess.run(["git", "add", "-A"], check=True)
subprocess.run(["git", "commit", "-qm", f"feito: {item['id']}"], check=True)
print(f"commit: feito: {item['id']}")
Terminal · ejecutar, "caer" y retomar
python3 ciclo.py
# cierra el terminal aquí, abre otro y vuelve a la carpeta
cd ~/ensaio-loop/estado
python3 ciclo.py && python3 ciclo.py && python3 ciclo.py

Los hashes cambian en tu máquina; el orden y los mensajes no.

Cambia la línea de la "acción" por una llamada al agente (codex exec o claude -p) y la de la "verificación" por una prueba que se ejecute de verdad. El resto (releer, un ítem, marcar solo con prueba, commit) queda igual. La verificación de esta versión de juguete es débil a propósito: solo comprueba que el archivo existe (nivel 2 en la escala de la clase 6).

Sesión descartableDiseña para el peor caso: la próxima sesión no recuerda nada y puede caerse en medio.
Vuelve a leer antes de actuarLa lista con passes, el archivo de progreso y el git log dicen dónde quedó; el resumen de la conversación no.
